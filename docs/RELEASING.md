# Releasing

The Git repository contains source code only. Windows installers are generated by GitHub Actions or on a maintainer's machine; they are never committed to the repository.

## Source release checklist

1. Update the version in:
   - `package.json`
   - `src-tauri/Cargo.toml`
   - `src-tauri/tauri.conf.json`
2. Update `CHANGELOG.md`.
3. Run:

```powershell
npm install
npm run typecheck
npm run build
cargo check --manifest-path src-tauri\Cargo.toml
npm run tauri:dev
```

4. Verify manual use with AI disabled.
5. Verify no personal data, credentials, databases, generated files, `.exe`, or `.msi` files are staged.
6. Commit `package-lock.json` and `src-tauri/Cargo.lock` after dependency resolution.

## GitHub Releases

The `Release Windows` workflow is manual. It uses the version in `tauri.conf.json`, builds the Windows installers, creates a matching `v<version>` tag/release, and uploads the bundles as release assets.

In GitHub:

1. Open **Actions**.
2. Select **Release Windows**.
3. Choose **Run workflow** from the intended release commit/branch.
4. Review the generated draft release.
5. Publish it when ready.

The installers live in GitHub Releases, not in Git history.

## Local installer build

A maintainer can also build locally:

```powershell
npm run tauri:build
```

The bundles are generated under:

```text
src-tauri\target\release\bundle\
```
